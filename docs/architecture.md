# Устройство npa-ocr

Документ описывает конвейер распознавания и роли модулей. Детали алгоритмов —
в докстрингах модулей, ход разработки и эксперименты — в
[`history/plan.md`](history/plan.md).

## Конвейер документа

`ocr_document()` (`src/npa_ocr/ocr.py`) обрабатывает PDF постранично:

1. **Сохранённый результат.** Если в каталоге страниц есть результат,
   полученный с теми же параметрами, страница берётся из него.
2. **Текстовый слой.** Страница, из которой извлекается не меньше 20 знаков,
   берётся как есть, без OCR.
3. **Проверка памяти.** Перед страницей-сканом проверяется свободная память;
   при нехватке распознавание останавливается с ошибкой, а не подвешивает систему.
4. **Рендер и поворот.** Страница рендерится в PNG (200 DPI) и при
   необходимости поворачивается по Tesseract OSD.
5. **Таблицы** — движком `tatr` или `vlm` (см. ниже).
6. **Текст вне таблиц** — Tesseract; слова в рамках таблиц пропускаются.
   Затем, в зависимости от режима, — удаление меток, ИИ-эскалация, второе
   прочтение и восстановление формулы должности подписанта.
7. **Сохранение страницы** — атомарно, в `<out>.pages/page_NNNN.json`.

После всех страниц убираются колонтитулы, с движком `vlm` сшиваются таблицы,
продолжающиеся на следующей странице, и собирается DOCX.

## Движки

| Задача | Движок | Модуль |
|---|---|---|
| Текст вне таблиц | Tesseract (rus) | `ocr.py` |
| Области таблиц | TATR (`table-transformer-detection`), уточнение — PaddleOCR PPStructureV3 | `table_structure.py`, `ocr.py` |
| Структура таблицы | TATR (`table-transformer-structure-recognition`) | `table_structure.py` |
| Текст ячеек | RapidOCR (eslav_PP-OCRv5, ONNX Runtime) | `ocr.py` |
| Перепроверка узких таблиц | img2table | `ocr.py` |
| Таблицы `vlm` | DeepSeek-OCR в vLLM + сетка по линиям | `vlm_tables.py`, `vlm_reread.py` |
| Метки `vlm` | qwen3-vl в Ollama + DeepSeek-OCR | `vlm_marks.py` |
| Второе прочтение текста | DeepSeek-OCR | `vlm_text.py` |
| ИИ-эскалация `tatr` | qwen3-vl в Ollama | `mark_detection.py`, `ai_escalation.py` |

Каждый движок передаётся в `ocr_document()` функцией. В работе это настоящие
модели, в тестах — подмены на сохранённых ответах. Движки по умолчанию
создаются при первой странице-скане, тяжёлые выгружаются между этапами, чтобы
не находиться в памяти одновременно.

### Почему разные движки

- Уверенность PaddleOCR не отличает текст, повреждённый печатью, от чистого
  (0.9+ у обоих), а уверенность Tesseract в целом отличает. Поэтому текст вне
  таблиц читает Tesseract, и его уверенность определяет выделение.
- PaddlePaddle требует AVX2: без него процесс падает с SIGILL при импорте.
  Текст ячеек читает RapidOCR (та же модель в ONNX Runtime), а PPStructureV3
  загружается, только если импорт paddle проходит в подпроцессе.
- Tesseract с русским словарём не знает римских цифр, латинских переменных,
  индексов и формул; их берёт второе прочтение DeepSeek-OCR.

## Движок таблиц `tatr`

1. TATR ищет области таблиц; если найдена хотя бы одна, их уточняет PaddleOCR,
   который разделяет соседние таблицы.
2. Для каждой области: текст фрагмента, структура TATR, удаление пустых
   строк и столбцов, растяжение строк до текста, разбиение слишком высоких строк.
3. Каждая ячейка распознаётся отдельно (RapidOCR по фрагменту с полем и
   увеличением); отбрасываются ложные объединения.
4. Сетка, похожая на абзац текста, а не на таблицу (низкая заполненность
   столбцов, 1×1), отбраковывается.
5. Узкая таблица (большой отступ справа) и страница, где TATR ничего не нашёл,
   перепроверяются через img2table.

## Движок таблиц `vlm`

1. DeepSeek-OCR распознаёт страницу целиком в режиме блоков с координатами;
   ответ используется и для таблиц, и для меток, и для второго прочтения текста.
2. Сетка таблицы строится по линиям разлиновки скана; ячейки DeepSeek
   сопоставляются ячейкам сетки по черновому тексту Tesseract и положению.
3. Сомнительные ячейки (текст только от Tesseract, пустые с напечатанным
   текстом, расхождения) читаются повторно по фрагменту ячейки.
4. Если сетка не построилась, берётся HTML DeepSeek как есть.
5. Если vLLM недоступен, таблицы до конца документа распознаются движком
   `tatr`; такие страницы сохраняются с другими параметрами и при следующем
   прогоне распознаются через vLLM.

Работа с vLLM через шлюз `vlm_gate` описана в его докстринге и в README.

## Печати, штампы, подписи

- **С `vlm` и `--ai-escalation`** (`vlm_marks.py`): qwen3-vl находит рамки
  меток на страницах, где они вероятны; текст меток удаляется, слова документа
  рядом сверяются с DeepSeek-OCR, шапка органа под краем штампа дописывается по
  `authority_name`.
- **С `tatr` и `--ai-escalation`** (`mark_detection.py`, `ai_escalation.py`):
  скопления неуверенных слов классифицирует qwen3-vl; текст под меткой,
  перекрывающей документ, восстанавливается одним запросом на всю метку,
  служебные метки (штамп регистрации, электронная подпись) удаляются.
- **Всегда при `authority_name`**: формула должности подписанта, повреждённая
  печатью, восстанавливается по правилам оформления (ФИО — никогда).

Если Ollama недоступна, документ распознаётся дальше без этой обработки.

## Второе прочтение текста

`vlm_text.py` выравнивает слова DeepSeek-OCR и Tesseract в рамке каждого блока и
заменяет только короткие расхождения рядом с совпавшими словами, если
выполнено правило своего вида: римская цифра или диапазон (по похожести
начертания), латинская переменная (не двойник и не транслит русской буквы),
индекс или степень, формула в строке, цифра, слитая со словом. Блок формулы
заменяет строки Tesseract в своей рамке.

## Сборка DOCX

`build_docx()`:

- строки склеиваются в абзацы по геометрии: отступ первой строки,
  центрирование, короткая строка и большой зазор заканчивают абзац;
- таблицы — таблицами Word с объединениями; непрямоугольное объединение
  пропускается без потери текста;
- формулы — формулами Word (LaTeX → MathML → OMML, `docx_math.py`), индексы —
  подстрочным и надстрочным шрифтом; формула, которую не удалось перевести,
  пишется исходным LaTeX и выделяется;
- неуверенный и восстановленный текст выделяется жёлтым, в начале документа —
  пояснение.

## Сохранение страниц

Результат страницы (блоки с координатами, таблицы, признаки уверенности,
разметка) сохраняется в JSON вместе с параметрами распознавания (`meta`):
DPI, порог, орган, движок, поворот, размер PDF, версии путей `vlm` и меток.
Страница берётся из файла, только если параметры совпадают; при изменении
алгоритма версия в `meta` повышается, и страницы распознаются заново.

## HTTP API

`server.py` принимает PDF и создаёт задание; `job_runner.py` запускает CLI
подпроцессом, следит за ним и разбирает ход распознавания из stderr.
Подпроцесс, завершившийся по сигналу (случайный SIGILL при первом выводе
модели на CPU без AVX2), перезапускается до двух раз и продолжает с
сохранённых страниц.
