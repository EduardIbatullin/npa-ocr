# npa-ocr

Распознавание PDF-сканов без текстового слоя в DOCX с таблицами, формулами и
выделением неуверенно распознанного текста.

Пакет принимает путь к PDF и ничего не знает о том, откуда документ взялся:
его можно использовать отдельно или подключить к другому сервису через
[HTTP API](#http-api).

## Возможности

Чистовой DOCX создаётся без подписей «Источник: PDF…» и без принудительных
переходов между страницами скана. Для исследовательского экспорта используется
`--diagnostic`. Метаданные `source_pages` сохраняются в обоих режимах.

После OCR рядом с DOCX сохраняется `<имя>.review.json` с адресами помеченных
мест. Отсутствие пометки не является доказательством правильности текста.
Результат формируется исключительно автоматическим конвейером. Ручные и
точечные исправления DOCX, постраничных данных и подстановки для конкретного PDF
запрещены. Визуальная сверка нужна для диагностики и тестовых эталонов.
Неустранённые ошибки фиксируются в [открытых вопросах](docs/open-questions.md):
рукописный текст, дополнительное чтение `[не распознано]`, мелкие ошибки без
изменения смысла. Отчёт контроля не является механизмом исправления документа.

- Страницы с текстовым слоем берутся как есть, распознаются только сканы.
- Текст вне таблиц — Tesseract; строки склеиваются в абзацы по геометрии
  (отступ, выравнивание по центру, зазоры), колонтитулы и номера страниц
  убираются.
- Таблицы — настоящие таблицы Word с объединёнными ячейками. Два движка:
  - `tatr` (по умолчанию) — Table Transformer и RapidOCR на CPU;
  - `vlm` — DeepSeek-OCR в vLLM на GPU, структура — по линиям разлиновки скана;
    сомнительные ячейки читаются повторно, таблицы, продолжающиеся на следующей
    странице, сшиваются.
- С движком `vlm` текст сверяется со вторым прочтением DeepSeek-OCR: римские
  цифры, латинские переменные, индексы и степени исправляются, формулы
  становятся формулами Word.
- Печати, штампы и подписи: с `vlm` текст меток удаляется, с `tatr` —
  восстанавливается текст, перекрытый меткой (локальная VLM в Ollama).
- Страницы, лежащие на боку, поворачиваются по Tesseract OSD.
- Неуверенно распознанный и восстановленный текст выделяется в DOCX жёлтым.
- Служебные ответы моделей не попадают в текст как обычные значения;
  нечитаемые напечатанные ячейки обозначаются явно. Повторное чтение не
  снимает пометку проверки автоматически.
- Короткие числовые графы, химические формулы и категории работ дополнительно
  проверяются по фрагментам скана. Восстановление структуры таблиц учитывает
  разрывы рамки и продолжение на следующей странице.
- Страницы исходного PDF доступны в метаданных и диагностическом экспорте для сверки.
- DOCX создаётся на листе A4 с полями по 1 см; ширины таблиц используют
  доступную область страницы.
- Химические графы перепроверяются на увеличенных фрагментах. Положение
  знаков относительно строки помогает различать буквы и нижние индексы.
- Результат каждой страницы сохраняется: прерванное распознавание
  продолжается с места остановки.

Устройство конвейера — [`docs/architecture.md`](docs/architecture.md), история
изменений — [`CHANGELOG.md`](CHANGELOG.md).

Ограничения перед выпуском в прод — [открытые вопросы](docs/open-questions.md),
включая нерешённые направления распознавания и ограничения компоновки.

## Установка

Нужны Python 3.11+ и Tesseract с русским языком (`tesseract-ocr` и
`tesseract-ocr-rus`; на Windows — `winget install tesseract-ocr.tesseract`).

```bash
pip install -e ".[dev]"       # ядро и тесты: юнит-тесты не загружают модели
pip install -e ".[models]"    # модели таблиц и OCR: torch, PaddleOCR, RapidOCR — несколько ГБ
pip install -e ".[server]"    # HTTP API
```

### Docker

Образ содержит Tesseract, все зависимости и модели (загружаются при сборке).
Версии пакетов закреплены в [`constraints.txt`](constraints.txt), поэтому сборка
с нуля даёт проверенный набор.

```bash
docker build -t npa-ocr .
docker run --rm -v "$PWD":/data npa-ocr /data/scan.pdf --out /data/out.docx
```

Распознавание таблиц на CPU требует больше 12 ГБ памяти; контейнеру стоит дать
запас (`docker run --memory 24g …`).

## Использование

### Командная строка

```bash
npa-ocr scan.pdf --out result.docx
npa-ocr scan.pdf --out result.docx --authority-name "Правительство Российской Федерации"
npa-ocr scan.pdf --out result.docx --table-engine vlm --ai-escalation
```

| Параметр | Назначение |
|---|---|
| `--out` | Выходной DOCX; по умолчанию `<pdf>.docx` |
| `--authority-name` | Орган, издавший акт: по нему восстанавливаются шапка и формула должности подписанта, повреждённые печатью или штампом (ФИО не восстанавливается) |
| `--table-engine {tatr,vlm}` | Движок таблиц; если vLLM недоступен, `vlm` переходит на `tatr` до конца документа |
| `--ai-escalation` | Обработка печатей, штампов и подписей через VLM в Ollama |
| `--dpi` | Разрешение рендера страниц (200) |
| `--confidence-threshold` | Порог уверенности Tesseract, ниже которого слово выделяется (60) |
| `--pages-dir` | Каталог результатов страниц; по умолчанию `<out>.pages` |
| `--no-resume` | Распознать все страницы заново |
| `--min-free-mb` | Минимум свободной памяти перед страницей, МБ; `0` — не проверять |
| `--no-auto-rotate` | Не поворачивать страницы по OSD |

### Python

```python
from npa_ocr.ocr import ocr_document

result = ocr_document("scan.pdf", "result.docx", table_engine="vlm")
print(result.docx_path, len(result.pages))
```

### HTTP API

Тот же образ запускает сервер асинхронных заданий. Каждое задание выполняется
подпроцессом CLI, поэтому сбой распознавания не роняет сервер. Одновременно
выполняется одно задание: пока оно идёт, `POST /jobs` отвечает `409`.

```bash
docker run --rm -p 8000:8000 --entrypoint uvicorn npa-ocr \
    npa_ocr.server:app --host 0.0.0.0 --port 8000
```

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/jobs` | Загрузить PDF (`file`, необязательно `authority_name`) → `{"job_id": …}` |
| `GET` | `/jobs/{job_id}` | Состояние: `status`, `percent`, `page`, `total_pages`, `page_status`, `steps`, `elapsed_seconds`, `error` |
| `GET` | `/jobs/{job_id}/result` | Готовый DOCX (`404`, пока задание не завершено) |
| `POST` | `/jobs/{job_id}/cancel` | Отменить задание |
| `GET` | `/health` | Проверка готовности |

```bash
curl -F "file=@scan.pdf" -F "authority_name=Правительство Российской Федерации" \
     http://localhost:8000/jobs
curl http://localhost:8000/jobs/<job_id>
curl -o result.docx http://localhost:8000/jobs/<job_id>/result
```

Движок таблиц сервера задаёт переменная `NPA_OCR_TABLE_ENGINE`; ИИ-обработка
меток в задании включена всегда.

### Шлюз vLLM

vLLM с DeepSeek-OCR занимает около 10 ГБ видеопамяти всё время, пока запущен.
Если GPU общая, npa-ocr обращается к vLLM через шлюз `python -m npa_ocr.vlm_gate`:
он запускает контейнер vLLM по первому запросу (холодный старт — 2–3 мин) и
останавливает его после простоя. Шлюзу нужен сокет Docker. Пример развёртывания —
сервисы `ocr`, `vlm-gate` и `vlm` в `docker-compose.yml`
[npa-downloader](https://github.com/EduardIbatullin/npa-downloader).

## Конфигурация

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `VLLM_URL` | `http://localhost:8001/v1` | OpenAI-совместимый API vLLM или шлюза |
| `VLLM_MODEL` | `deepseek-ocr` | Имя модели в vLLM (`--served-model-name`) |
| `VLLM_TIMEOUT` | `900` | Таймаут запроса к vLLM, с (с запасом на холодный старт) |
| `OLLAMA_URL` | `http://localhost:11434` | Ollama для обработки меток |
| `NPA_OCR_MARKS_MODEL` | `qwen3-vl:8b` | Модель Ollama для поиска меток |
| `NPA_OCR_TABLE_ENGINE` | `tatr` | Движок таблиц HTTP API |
| `NPA_OCR_JOBS_DIR` | `jobs` | Каталог файлов заданий HTTP API |
| `TESSERACT_CMD` | — | Путь к Tesseract, если его нет в `PATH` |
| `VLM_CONTAINER` | `npa-vlm` | Шлюз: имя контейнера vLLM |
| `VLM_UPSTREAM` | `http://vlm:8000` | Шлюз: адрес vLLM в сети Docker |
| `VLM_IDLE_MIN` | `10` | Шлюз: простой до остановки vLLM, мин |
| `VLM_START_TIMEOUT` | `600` | Шлюз: наибольшее время старта vLLM, с |
| `VLM_GATE_PORT` | `8000` | Шлюз: порт |
| `DOCKER_SOCKET` | `/var/run/docker.sock` | Шлюз: сокет Docker |

## Внешний контракт CLI

На него можно опираться при встраивании CLI в другой сервис.

- **stdout** после завершения — один JSON: `{"docx": "...", "pages": N,
  "pages_ocr_applied": M}` с кодом возврата 0 или при нехватке памяти
  `{"status": "insufficient_memory", "message": "..."}` с кодом 1.
- **stderr** по ходу работы:
  - `[ 23.8%] страница 5 из 21: распознаётся` (`готово`, `текстовый слой`,
    `взято из сохранённого прогона`);
  - `  [стр. 5] таблицы: структура и текст ячеек: 1 мин 39 с` — длительность шага;
  - кодировка задаётся окружением (`PYTHONIOENCODING`); без неё на Windows при
    перенаправлении в файл обычно cp1251.
- **Файлы** рядом с `--out`: `<out>.pages/page_NNNN.json` — результаты страниц
  (берутся повторно при тех же параметрах), `<out>.timings.json` — длительность
  шагов.

Формат проверяют тесты `tests/unit/test_cli.py` и `tests/unit/test_ocr.py`.

## Разработка

```bash
pytest            # юнит-тесты на подменённых движках: без сети и без моделей
pytest -m live    # распознавание настоящего скана (нужны модели и Tesseract; минуты)
```

Юнит-тесты движков DeepSeek-OCR и qwen3-vl работают на сохранённых ответах
моделей и словах Tesseract (`tests/unit/fixtures`).

## Ограничения

- Таблицы без линий сетки движок `tatr` распознаёт неточно; `vlm` берёт для
  них HTML DeepSeek-OCR как есть.
- Печать может исказить слово при высокой уверенности Tesseract: такие
  искажения выделяются не всегда.
- Восстановленный и неуверенный текст выделяется, но не проверяется
  автоматически — его нужно сверить со сканом.
- Пиковая память распознавания на CPU (PaddleOCR и TATR) — более 12 ГБ.
